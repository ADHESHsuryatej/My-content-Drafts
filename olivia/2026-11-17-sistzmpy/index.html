Building a notification preference centre users actually use with SuprSend

A notification preference center is the page where users choose which channels, topics and frequencies they want. Get it right, and users stay subscribed because the messages feel relevant. Get it wrong, and they hit unsubscribe or, worse, mark you as spam. As a product manager who has shipped preference centres for hiring-marketplace emails and in-app feeds, I've seen the difference a well-designed centre makes on retention. SuprSend handles the heavy lifting (categories, channels, precedence, digests, quiet hours and multi-tenant overrides) so your team can focus on the user experience instead of the infrastructure. You can link the centre to APNs for iOS push, FCM for Android push, and Web Push for browser notifications.

The problem: preference centres that nobody opens

Most preference centres are buried in a settings menu, use jargon like "transactional vs promotional," and force users to tick ten checkboxes before they understand what any of them means. Twilio's guide on email preference centres recommends clear descriptions, frequency management and an easy opt-down path instead of a binary subscribe/unsubscribe choice. If your centre doesn't offer that middle ground, users leave the list entirely. You can also follow DMARC alignment to protect your sender reputation.

How SuprSend models preferences: categories, channels and precedence

SuprSend organises preferences around categories (e.g. "security alerts," "weekly digest," "new candidate matches"), each mapped to one or more channels (email, push, in-app, Slack, SMS, WhatsApp). The precedence model resolves conflicts in a fixed order: user choice > tenant admin default > category default. That means a user can mute "weekly digest" on email while keeping it in the in-app feed, and a tenant admin can set a baseline that users can still override. Categories can be hidden per tenant, so the same workspace serves different customer brands without code changes. For email deliverability, align with RFC 5321 and RFC 8058 for one-click unsubscribe.

Embedding the hosted centre vs building a headless UI

SuprSend provides a hosted preference centre you can embed with a single React component or an iframe. The component inherits your theme variables, so it looks native without CSS overrides. If you need a custom layout (say, a slide-over panel inside your dashboard) you can call the headless API, fetch the category tree with current states, and render your own controls. Both paths read and write the same backend, so a change in the hosted view reflects instantly in your custom UI. The in-app inbox component can surface a "Manage notifications" link that opens the centre in context, keeping users in the product.

Digest frequency, quiet hours and timezone-aware delivery

Categories can be configured as digests with a fixed schedule (daily at 8 a.m., weekly on Monday) or a user-chosen cadence. SuprSend stores each user's timezone and sends the digest at their local time, not yours. Quiet hours let users block non-urgent channels (email, push) during a window like 10 p.m.–7 a.m. while still allowing critical alerts (security, billing) through. The batching and digest engine lives on the Business plan ($250/mo billed annually) and counts as a single notification per recipient per digest, which keeps costs predictable.

Multi-tenant overrides: admin defaults, mandatory channels, hidden categories

For B2B products, SuprSend's multi-tenant model lets tenant admins set default preferences for their organisation, mark channels as mandatory (e.g. "security alerts must go to email"), and hide categories that don't apply to their plan. Sub-tenants up to five levels inherit these settings unless they override them. This is gated to Enterprise or a paid add-on, so single-tenant apps don't pay for complexity they don't need. If open-source multi-tenancy matters more than depth, Novu is the pick.

What using it actually involves: setup, plan needed, who touches it

  1. Define categories in the dashboard or via the Management API (JSON Schema validated).
  2. Choose embedding: drop in the React component or build headless with the REST endpoints.
  3. Configure precedence defaults per category and per tenant.
  4. Enable digests and quiet hours on the Business plan.
  5. Test in the sandbox workspace with test vendors before promoting to production.

Engineering does the initial integration. After that, product and growth teams adjust categories, schedules and defaults without code changes. The SuprSend Agent (Cmd+/ in the dashboard) can help build workflows and templates, debug delivery, and pull analytics.

Caveats: Business plan for preferences, no embeddable editor for your customers, initial configuration effort

Preferences, digests, batching and objects require the Business plan ($250/mo billed annually). The Free and Essentials tiers only support basic channel opt-outs. SuprSend does not provide an embeddable template editor for your end customers (Courier does) so if your customers need to brand their own notification emails, you'll build that layer yourself. The first configuration pass (categories, translations, tenant defaults, quiet-hour windows) takes real design time; treat it like a feature, not a checkbox.

SuprSend's preference model gives you the building blocks: categories, precedence, digests, quiet hours and multi-tenant overrides. Wire them into your UI, set sensible defaults, and users get a centre they actually understand and use.
