How to set up APNs push notifications in iOS

Push notifications are messages delivered to a user's device even when your app isn't open. Get the APNs in iOS setup right, and your server reaches every iPhone reliably; get it wrong, and users never see the alerts you built.

We'll walk through native APNs integration using token-based authentication, the entitlements Xcode adds, device-token handling, and the HTTP/2 call your provider server makes. No vendor SDKs required.

Prerequisites

Before you start, make sure you have:

  • A paid Apple Developer Program membership with Admin access.
  • Xcode installed (Xcode 14 or later for simulator support).
  • A backend server that can open HTTP/2 connections and sign ES256 JWTs (Node, Go, Python, Java all work).

Enabling push capability and entitlements in Xcode

Open your project, select the app target, and go to Signing & Capabilities. Click + Capability, search for Push Notifications, and add it. Xcode injects the aps-environment entitlement into your app bundle. The value is development when you build with a development provisioning profile and production for a distribution profile. This entitlement tells APNs which environment your device token belongs to.

If you skip this step, registerForRemoteNotifications() fails with a missing-entitlement error.

Choosing token-based (.p8) vs certificate-based (.p12) auth

Apple supports two ways to authenticate your provider server:

  • .p8 authentication key (token-based): a single key per Apple Developer team, no expiry, works for both sandbox and production, and covers every app under that team.
  • .p12 certificate (certificate-based): app-specific, expires after one year, and must be renewed annually.

OneSignal and AWS SNS both recommend the.p8 approach because it removes certificate rotation from your operational calendar. We'll use token-based auth for the rest of this guide.

Generating and downloading a.p8 authentication key

  1. Sign in to the Apple Developer portal.
  2. Go to Certificates, Identifiers & Profiles → Keys.
  3. Click +, choose Apple Push Notifications service (APNs), and enable Sandbox & Production.
  4. Name the key, register it, and download the.p8 file immediately. You cannot download it again.
  5. Note the Key ID (10-character string like ABC123DEFG) and your Team ID (also 10 characters, shown at the top right of the portal).

Store the.p8 file securely; it's the private key your server uses to sign every JWT.

Registering the app and receiving a device token at launch

Every time your app launches, it must ask APNs for a device token. In iOS, call UIApplication.shared.registerForRemoteNotifications() early in application(_:didFinishLaunchingWithOptions:) source. On success, the system calls your app delegate's application(_:didRegisterForRemoteNotificationsWithDeviceToken:) with a Data object. Convert it to a hex string and send it to your provider server immediately.

func application(_ application: UIApplication,
                 didRegisterForRemoteNotificationsWithDeviceToken deviceToken: Data) {
    let token = deviceToken.map { String(format: "%02.2hhx", $0) }.joined()
    sendDeviceTokenToServer(token)
}

Also implement application(_:didFailToRegisterForRemoteNotificationsWithError:) to log failures (network, entitlements, sandbox vs production mismatch) and retry later.

Important: never cache the token locally. APNs issues a new token when a user restores from backup, reinstalls the OS, or installs the app on a new device. Fetch it at every launch.

Building a JWT provider authentication token for APNs

APNs expects a signed JWT in the Authorization: bearer <token> header of every HTTP/2 request. The token header must contain alg: "ES256" and kid: "<Key ID>". The payload requires iss (your Team ID) and iat (issued-at timestamp, seconds since epoch, UTC). Sign the JWT with the private key from your.p8 file using the P-256 curve and SHA-256.

import jwt, time
​
def apns_auth_token(team_id: str, key_id: str, p8_path: str) -> str:
    with open(p8_path) as f:
        private_key = f.read()
    payload = {
        "iss": team_id,
        "iat": int(time.time())
    }
    headers = {"alg": "ES256", "kid": key_id}
    return jwt.encode(payload, private_key, algorithm="ES256", headers=headers)

APNs rejects tokens older than one hour with a 403 ExpiredProviderToken error. Generate a fresh token before each batch of sends, or cache it and refresh at 55 minutes.

Sending a notification via HTTP/2 POST to APNs

Your provider server POSTs to https://api.push.apple.com/3/device/{device_token} over HTTP/2. The request body is a JSON payload (max 4 KB, 5 KB for VoIP). Required headers:

apns-topic. Your app's Bundle ID (e.g., com.example.app).

authorization. bearer <JWT>.

apns-push-type. alert, background, voip, etc.

apns-priority. 10 (immediate) or 5 (power-efficient).

{
  "aps": {
    "alert": { "title": "Deploy failed", "body": "Build #231 exited with code 1" },
    "sound": "default",
    "badge": 1
  }
}

APNs returns 200 on acceptance. A 410 means the device token is invalid (app uninstalled); remove it from your store. A 403 usually means an expired or malformed JWT. Implement exponential backoff and retry on 429 or 5xx.

Testing with the iOS simulator and sandbox environment

Since Xcode 14, the iOS simulator can register with the sandbox APNs environment and receive a device token. Run your app on a simulator, grant the permission prompt, and watch the delegate callback fire. Send a test notification from your server to the sandbox endpoint (api.sandbox.push.apple.com) using the same JWT and the simulator's token. Verify the payload appears in the simulator's notification center.

If the delegate methods never fire on a CI runner, check that the VM supports the simulator's network stack; GitHub Actions macOS runners work, but nested virtualization sometimes blocks the APNs handshake.

Gotchas: token rotation, payload size, environment mismatch

  • Device tokens rotate. A restore, reinstall, or OS upgrade produces a new token. Always fetch at launch and update your server.
  • Payload limit is 4 KB (5 KB for VoIP). APNs rejects larger bodies with 413.
  • Environment mismatch. A development token sent to the production endpoint (or vice versa) yields 400 BadDeviceToken. Match the aps-environment entitlement to the APNs host you call.
  • JWT expiry. Tokens older than one hour are rejected. Refresh proactively.

Wrapping up

You now have the full native flow: Xcode entitlement →.p8 key → device token at launch → hourly JWT → HTTP/2 POST to APNs. From here you can add:

  • Retry queues with exponential backoff for transient APNs errors.
  • Batching and digest logic so users don't get spammed.
  • A multi-channel layer (email, in-app, Slack) that respects user preferences.
