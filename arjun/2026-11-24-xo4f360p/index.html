How to Build In-App Notifications

In-app notifications are messages users see inside your product while they're using it. They work alongside email and push to keep users informed without leaving the app. Get the implementation right and users act on updates instantly. Get it wrong and they miss critical information or disable notifications entirely.

We'll wire a real-time in-app notification feed from backend event to frontend component using Next.js, the SuprSend Node SDK, and the in-app inbox React package. You'll end up with a working feed that respects user preferences and supports digests.

Prerequisites

  • Node 20 or later
  • A SuprSend account (free tier works) or a Firebase project for push fallback
  • A React or Next.js application

Setting up the project

Initialize a Next.js app and install the SuprSend packages. The Node SDK handles backend calls, while the in-app inbox package provides a drop-in React component.

npx create-next-app@latest my-app --typescript --tailwind --eslint
cd my-app
npm install @suprsend/node @suprsend/react-inbox

The @suprsend/node SDK authenticates with your workspace key and secret. The @suprsend/react-inbox package exports an <Inbox /> component that handles feed rendering, real-time updates, and user interactions. For a deeper walkthrough of this setup, see the SuprSend real-time notification tutorial and the app inbox product page.

Creating the notification workflow

In the SuprSend dashboard, create a workflow with an in-app channel node. Add a template that uses Handlebars for dynamic content, for example, {{actor_name}} commented on {{document_title}}. Enable user preferences on the workflow so recipients can opt out or choose digest frequency per category.

Workflows support branching, delays, and batching nodes. For a simple comment notification, a single in-app node is enough. The workflows documentation and templates guide cover the visual builder and JSON editing options.

Sending a notification from your backend

Create a server-side function that triggers the workflow. Use the Node SDK with your workspace credentials.

// lib/suprsend.ts
import { SuprSend } from '@suprsend/node';
​
const suprsend = new SuprSend({
  workspaceKey: process.env.SUPRSEND_WORKSPACE_KEY!,
  workspaceSecret: process.env.SUPRSEND_WORKSPACE_SECRET!,
});
​
export async function sendCommentNotification(
  userId: string,
  payload: { actorName: string; documentTitle: string; commentUrl: string }
) {
  await suprsend.workflow.trigger('comment_added', {
    distinct_id: userId,
    ...payload,
  });
}

Call this function from your API route or server action when a comment is created. The workflow runs, renders the template, and delivers to the in-app inbox. Verify delivery in the SuprSend dashboard logs, you'll see the workflow run, template render, and in-app delivery status. The notification system for SaaS post shows a complete example with error handling.

Rendering the in-app inbox on the frontend

Drop the <Inbox /> component into your layout. It needs a subscriber ID (your user's ID) and a SuprSend client key.

// components/NotificationBell.tsx
'use client';
​
import { Inbox } from '@suprsend/react-inbox';
import { useAuth } from '@/lib/auth';
​
export function NotificationBell() {
  const { user } = useAuth();
​
  return (
    <Inbox
      subscriberId={user.id}
      clientKey={process.env.NEXT_PUBLIC_SUPRSEND_CLIENT_KEY!}
      theme="light"
      position="bottom-right"
    />
  );
}

Add <NotificationBell /> to your root layout or a persistent header. The component handles WebSocket connections for real-time updates, read/unread state, and actions like marking all as read. Test by triggering a notification from your backend, the bell badge increments instantly. The app inbox product page and React inbox guide cover theming, headless mode, and mobile responsiveness.

Adding user preferences and digest controls

Users need control over what they receive and when. Embed the SuprSend preference center so they can opt out of categories or choose digest frequency (immediate, hourly, daily) per channel.

// app/settings/notifications/page.tsx
'use client';
​
import { PreferenceCenter } from '@suprsend/react-inbox';
import { useAuth } from '@/lib/auth';
​
export default function NotificationSettings() {
  const { user } = useAuth();
​
  return (
    <PreferenceCenter
      subscriberId={user.id}
      clientKey={process.env.NEXT_PUBLIC_SUPRSEND_CLIENT_KEY!}
    />
  );
}

The preference center respects the precedence: user settings override tenant defaults, which override category defaults. Quiet hours use the recipient's timezone. The preferences product page and notification preferences guide explain the schema and embedding options.

Testing and debugging

Use three layers to confirm everything works:

  1. SuprSend dashboard logs, filter by workflow, user, or status. See step-by-step execution: trigger received, template rendered, in-app delivered. Test mode lets you send to a test user without affecting production logs.
  2. Browser dev tools, open the Network tab, filter for WebSocket (ws) connections. Confirm the connection opens, receives the notification payload, and updates the badge count.
  3. Backend logs, verify the workflow trigger call returns a workflow_run_id and no errors.

Common issues: missing distinct_id on the trigger call, subscriber ID mismatch between backend and frontend, or the client key not exposed to the browser (prefix with NEXT_PUBLIC_ in Next.js). The dashboard docs and Go/WebSocket tutorial show debugging workflows.
